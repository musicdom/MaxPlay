# Подарки

Новый проект отложенных подарков для MAX.

## Что уже есть в коде
- Новый адаптивный интерфейс сервиса.
- Выбор повода и шаблона оформления.
- Создание подарка с текстом и пользовательским изображением.
- Хранение записи подарка в Neon Postgres.
- Загрузка изображений в Vercel Blob.
- Персональная ссылка для отправки в MAX.
- Закрытая страница подарка до назначенного времени.
- Серверное окно открытия: ровно 12 часов после назначенного времени.
- Фиксация получения подарка.
- MAX webhook для привязки пользователя через deep link.
- Cron endpoint для открытия срока, сгорания подарков и отправки уведомления получателю.

## Переменные окружения
- DATABASE_URL — Neon Postgres.
- BLOB_READ_WRITE_TOKEN — Vercel Blob.
- MAX_BOT_TOKEN — токен MAX-бота.
- MAX_BOT_USERNAME — username бота без @.
- CRON_SECRET — секрет для защищённого вызова cron.
- NEXT_PUBLIC_APP_URL — публичный URL приложения.

Шаблон значений находится в .env.example. Секреты нельзя хранить в Git.

## Как работает доставка в MAX
Получатель открывает ссылку на подарок и нажимает «Подключить уведомление в MAX». Это запускает бота с deep link payload, webhook связывает MAX user_id с подарком. В назначенное время cron отправляет личное сообщение с кнопкой открытия. MAX-бот может писать пользователю только после того, как тот сам запустил бота.

## Важно перед публичным запуском
Нужно подключить Neon, Vercel Blob, настроить MAX webhook и переменные окружения Vercel. Автоматический cron должен выполняться с подходящей частотой на выбранном тарифе Vercel. Полноценная авторизация профиля и MAX Mini App initData остаются следующим этапом: сейчас статус получения фиксируется в базе, но раздел профиля ещё не подключён.
